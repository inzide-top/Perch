# 账号模型配置

模型配置通过已认证的 `/api/model-settings` 接口按当前用户保存。数据库仅保存 AES-256-GCM 密文，密文绑定用户 ID；接口禁止缓存，只向当前用户返回解密后的配置供现有 AI 请求使用。浏览器仍保留本地缓存，退出登录会清理缓存，数据库记录保留。

上线步骤：

1. 生成 32 字节随机密钥：`node -e 'console.log(require("node:crypto").randomBytes(32).toString("hex"))'`。
2. 在 Railway 后端添加 `MODEL_CONFIG_ENCRYPTION_KEY`，值为生成的 64 位十六进制字符串。它不是模型供应商的 API Key，不要加 VITE 前缀，不要提交到 Git。所有后端实例使用同一密钥。
3. 发布代码并执行 `pnpm db:migrate`，创建 `user_model_settings` 表（启用 RLS，仅由认证后端访问）。
4. 部署环境变量变更，保存一份配置，退出再登录检查恢复；用另一个账号检查不能看到该配置。

密钥需持久保管并与数据库备份配套。不能每次部署重新生成；更换密钥须先用旧密钥解密并重新加密现有记录，否则无法读取。未配置或密钥错误时接口明确报错，不会回退到明文保存。

旧浏览器中仍存在的模型配置，会在账号尚无云端配置时自动迁移；账号已有配置时以云端为准。之前退出登录已经清除的本地配置无法找回，需要重新填写。当前配置与可复用列表作为一个整体保存，多设备同时编辑时最后一次成功保存生效。
